# 第一轮整体优化 · 2026-11-01（0.1.0 → 0.2.0）

接着创立会话之后的一次会话：用户在 Windows Terminal 里用 `cowait split` 把面板开在 Claude Code 旁边，
然后说“搞明白这个项目是做啥的，然后整体优化一下这个产品”，又补了一句“仔细看一下创立会话记录，然后就按你的想法去优化”。
这份文件记录做了什么、为什么、审阅意见怎么取舍。接手者先读 `AGENTS.md`。

## 1. 判断依据

重读创立会话后定下三条原则，所有改动都对着它们：

1. **激励要对齐**：竞品的通病是按等待时长给奖励（奖励空转）。同一类漏洞：按一下 `y` 就加能量，等于奖励按键，不是奖励审阅。
2. **别让人和 Claude 的工作脱节**：审阅是主线，游戏和学习是审完的奖励（创立会话建议的“一个钩子讲故事”：审完代码才能玩的终端游戏）。
3. **审阅覆盖率必须可信**：团队版靠它收费，能被刷出来的数字不值钱。

另外两个事实来自真实使用：
- 面板实际开在 40% 的分屏里，大约 60–70 列，而原来的界面是按 96 列设计和截图的：按键提示被截断、帮助页折行错乱、中文和英文混排时英文单词单独占一行。
- 开发 0.2.0 的这个长会话里，Claude 改了 150 处，面板生成了 150 张卡（队列封顶 80），用户审了 0 张，刷了 13 张卡、玩了 1 局。逐处审在长会话里不现实。

## 2. 改了什么

**审阅**
- 同一会话对同一文件的连续修改合到一张卡上（30 分钟窗口、每卡最多 20 处，Windows 路径不区分大小写和斜杠），卡上标“第 N 处”。
- diff 长行折行显示，不再截断；多项目时卡片标出项目名；改动类型中文化。
- 扫一眼不算审：出现后不到 `min(4 s, 0.6 s + 每改动行 0.08 s)` 就按 `y`，卡片照样通过，但不加能量、记为 `skimmed`、不计入覆盖率。刷卡同理（1.5 秒）。
- `S` 连按两次跳过整个队列（算跳过，不算审过）。

**留言（“不打断也能纠偏”）**
- `m` 随时给 Claude 留言，不必针对某张卡；标题栏显示等待送达的条数 `✎N`；Claude 收到后底栏提示“Claude 收到了你的留言”。
- 留言带项目目录和会话 ID，hook 只把留言交给对应的会话或项目里的会话（之前两个项目同时开着时，A 的留言可能被送进 B）。

**提醒与自动模式**
- 完成提醒写明这一轮做了什么：改动几处、测试过没过、金币、还剩几张待审。每日奖励之类改成不挡键的底栏提示。
- 新一轮开工不会把人从战斗里拽走；审完队列后的自动换模式只在用户还停在审阅页时生效（之前会把已经切到学习页的人拽回游戏，这是旧 bug）。
- 一轮超过平时的长度后，“预计”会往后重估，或者显示“比平时久”，不再显示一个已经过去的时间。
- 面板关着时发生的事，重新打开时安静补上，不响铃不弹提醒。
- 第一次用（从没收到过事件、也没装 hooks）停在审阅页并给出接入提示。

**窄屏**
- 全部界面按 60 列验证（测试里有 60×26 的溢出检查）；按键提示有长短两版；帮助页改成结构化的两列；自写了中日韩友好的折行（`src/text.ts`）；内容超高时只裁底部。

**其他**
- 从日志折叠来的状态最多 3 秒落盘一次（原来每个事件都整份写 `state.json`），用户操作立刻保存，滚动日志和退出时立刻保存。
- “用刚写的代码出题”按最新改动优先取材（合并卡片后旧逻辑会把最新的改动截掉）。
- `cowait stats` 把“转达的留言”单独列一行；`cowait demo` 也演示同一文件连改两次。
- README 配图全部改为浅色，由新的跨平台脚本 `npm run media` 从真实面板录制（无头 Chrome + ffmpeg），替换了只能在 Linux 跑的 Python 脚本；删掉了 README 没用到的 `alert-*.png`，`note-*.png` 由 `review-*.png` 取代。README 标语改为以审阅为主线。

## 3. 独立审阅（/code-review）的意见和取舍

| 意见 | 处理 |
|---|---|
| 项目匹配允许父目录，开在 `~/code` 或根目录的会话会吞掉子项目的留言 | 属实。改为只认同目录或子目录，另加会话 ID 精确匹配（Claude 换目录也能收到） |
| “扫一眼”计时在审阅页卸载（看帮助、切页）后重置 | 属实。改为模块级记录首次出现时间 |
| 延迟落盘后，面板 3 秒内被杀会在重启时重放提醒 | 属实，而且“面板关着时 Claude 完成、重开后补响铃”原来就有。统一修：信号带时间，15 秒以前的不提醒 |
| 自由留言也计入 `stats` 的“已转达”，口径混了 | 属实。单独一行 |
| 合并按原始路径比较；合并没有时间限制 | 属实。`normPath` + 30 分钟窗口 |
| 出题截断会丢掉合并卡片里最新的改动 | 属实。`describeChanges` 最新优先 |
| 日志滚动后从别的目录打开面板会误报“没接入” | 属实。有过任何轮次或卡片就不提示 |
| hook 认领前多读一次留言文件，拖慢热路径 | 部分采纳。没有留言时仍只读一次目录；有留言时每条多读几十字节，相对 39 ms 的 Node 启动可以忽略。建议的替代方案（文件名带目录哈希、先认领再改回）要么做不了子目录匹配、要么引入竞态，所以保留先读再认领，但去掉了认领后的第二次读取 |
| diff 折行和文字折行是两套逻辑 | 属实。合并到 `src/text.ts`；`useLine` 改用 `useRefState` |
| AGENTS.md 没更新 | 本来就排在最后，已更新 |

## 4. 验证

- 测试从 64 个增加到 104 个，全部通过；`tsc` 无错误。新增：合并卡片、扫一眼、留言路由（父目录、根目录、会话 ID、Windows 路径）、送达信号、等待重估、折行（中英、标点）、出题取材、60 列全界面溢出、`m` 留言与 Esc、战斗中不被打断、旧事件不提醒、退出时落盘、`S` 跳过全部、看完帮助后计时不重置。
- 用渲染脚本按 60 列把中英文每个界面画出来逐一目检；配图录完后抽帧检查（合并卡片、留言送达、完成提醒、折行、战斗、学习）。
- 0.2.0 的 hook 在开发它的真实 Claude Code 会话里一直在用（每次打包都替换了 `dist/hook.js`）。
